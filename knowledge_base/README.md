# 演示知识库（Demo Knowledge Base）

这个文件夹里的三份 Markdown 文件，是给后续 RAG（检索增强生成）功能准备的**模拟语料**。

目前项目还没有真实客户资料，所以先用这套自制的演示资料，把检索、来源引用和拒答的流程跑通。

---

## 重要声明

- **这是模拟语料，不是客户数据。** 所有内容都是本项目自己编写的演示资料，与任何真实教学机构、真实课程、真实学员都没有关系。
- **可以公开提交。** 内容为原创撰写，不含任何第三方教材原文，可以安全地推到公开的 GitHub 仓库。
- **不是教学权威资料。** 内容以准确、简洁为目标，但仅用于演示检索流程，不应作为正式学习依据。
- **不含敏感信息。** 没有学生隐私、没有付费课程原文、没有版权不明的转载内容。

---

## 文件说明

| 文件 | 覆盖主题 |

| `grammar_present_perfect.md` | 现在完成时：基本结构、四种用法、since 与 for 的区别、和一般过去时的区别、常见错误 |

每份文件顶部都写明了来源和用途，方便日后核查。

---

## 为什么故意留了「资料里没有」的空白

这份语料**刻意不覆盖**某些话题，例如：

- 课程价格、优惠、退费政策
- 具体排课时间、开课日期、报名截止日
- 证书、考试、成绩评定
- 教师资历、机构背景、联系方式

这不是遗漏，而是**故意留出来的测试点**。

一个合格的 RAG 系统，在被问到这些内容时，应该明确回答「资料里没有相关信息」，而不是编一个听起来合理的答案。

> 编造，比答不出来严重得多——尤其是在企业场景里。

## 后续怎么替换成真实资料

拿到授权之后，替换步骤很简单：

1. 删掉这个文件夹里原来的演示文件
2. 把授权资料放进来（建议同样用 Markdown，一份文件一个主题）
3. 更新本 README 的文件说明表
4. 确认新资料不包含个人信息、不含付费内容原文、版权清晰

**代码那边不需要改动**——只要文件还在 `knowledge_base/` 目录里，检索逻辑照常工作。

---

## 对资料格式的建议

为了让检索效果更好，新放进来的资料建议遵循：

- **一份文件只讲一个主题**。主题越集中，切分后每一段的含义越清晰，检索越准。
- **用小标题分段**。切分工具通常按标题和段落边界切，结构清楚切得就好。
- **保留完整的问答对**。FAQ 类资料如果只留答案、丢掉问题，检索时很难匹配到用户的问法。
- **避免超长段落**。一段超过 300 字就该拆开，否则切出来的块会混杂多个意思。
- **同一概念的说法保持一致**。一会儿叫「现在完成时」、一会儿叫「完成时态」，会让检索不稳定。
