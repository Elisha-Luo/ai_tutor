# AI 学习助手（ai_tutor）

一个网页版的英语学习助手：用 Flask 做界面，先从项目资料里检索相关片段，再让 DeepSeek **照着资料**回答，并把资料来源列出来。

**它同时也是一个「怎么写好一个聊天界面」的练习。** 界面上的每处细节——尤其是「点发送之后会发生什么」——都踩过坑，下面都写清楚了。

---

## 它做什么

- 中间是对话区，底部是输入框，按回车或点「发送」提问
- **正常的英语问题都会尽量回答**，分两种情况：
  - **资料里有依据** → 回答末尾列出**「资料来源」**（文件名 + 小节标题）
  - **资料里没有，但属于正常英语问题** → 用通用知识回答，并标明**「AI 通用知识回答」**
- 只有**课程业务事实**（价格、开课时间、证书等）资料没记录时，才会明确拒答 —— **绝不编造**
- 回答里的 Markdown（加粗、代码块、列表）会渲染成真正的排版，不是一堆星号
- 等待回答时有明确反馈：跳动的点、提示条、按钮变「思考中…」
- **每个浏览器看到的是自己的对话**，互不串话（靠一个存在 cookie 里的随机会话 ID 区分）
- **对话存在 SQLite 数据库里**，重启程序不会丢；不用登录，打开就能接着聊

> ⚠️ **关于「多轮对话」**：同一个浏览器里，**最近的 6 条**消息会作为**对话上下文**带给模型，
> 所以「刚才那句再改简单一点」「再给一个例子」这类追问接得上。
> 但它是**短期上下文，不是长期学习档案**：不跨浏览器、不跨设备，清掉 cookie 就等于换了个人。
> 而且**检索仍然只按你当前这个问题**进行。详见下面「已知限制」。

## 怎么运行

### 1. 装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置密钥

需要**三个**密钥，都是**从环境变量读取，不写死在代码里**（写死的话推到 GitHub 会被瞬间抓走）。

| 名字 | 干嘛的 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 调用 DeepSeek 用，在 https://platform.deepseek.com 申请 |
| `FLASK_SECRET_KEY` | Flask 用它给浏览器 cookie 签名，防止别人伪造 cookie 冒充成别的会话 |
| `INVITE_CODE_PEPPER` | 把邀请码算成摘要用的服务端密钥。数据库里只存摘要，没有它就反推不出邀请码 |

> ⚠️ **`INVITE_CODE_PEPPER` 是后加的。** 如果你的 `.env` 是很早以前建的，
> 里面没有这一项，应用会**直接启动失败**并明确告诉你缺什么 —— 这是故意的：
> 没配 pepper 就等于邀请码没有保护，宁可开不起来。
> 补上它：往 `.env` 里加一行 `INVITE_CODE_PEPPER=<一串你自己的随机值>`。

**推荐做法：用 `.env` 文件**

项目里有一个 `.env.example` 模板，照着复制一份就行：

```powershell
cd C:\Claude-Code\ai_tutor
Copy-Item .env.example .env     # 复制模板
notepad .env                    # 打开，把三个值换成你自己的
```

`.env` 会被 `.gitignore` 挡在仓库外面，**绝不会被推到 GitHub**——这是放密钥的正确位置。

`FLASK_SECRET_KEY` 必须换成一串够长够随机的字符，生成方法：

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

把打印出来的那串粘到 `.env` 里即可。

> ### ⚠️ 复制完 `.env.example` 之后，**必须把示例值换掉**
>
> `.env.example` 是提交进 Git 的**模板**，里面的值（`sk-在这里填你自己的密钥`）
> 公开可见，所以它**不可能是一个能用的密钥**。
> 复制完忘了改，程序照样启动、照样发请求，只是每一次都失败 ——
> 很容易白排查一轮。所以现在两个入口（`app.py` 和评测器）
> 都会在**发出任何网络请求之前**停住，直接提示：
>
> ```
> DEEPSEEK_API_KEY 仍是示例值，请配置真实密钥。
> ```
>
> 看到这句话，去把 `.env` 里那一行换成你自己的就行。

**另一种做法：直接设环境变量**

不想用 `.env` 的话，也可以在 Windows 上设一次（永久生效）：

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "你的密钥", "User")
[Environment]::SetEnvironmentVariable("FLASK_SECRET_KEY", "你的随机串", "User")
```

> ### ⚠️ 改完之后，**已经打开的终端和编辑器不会自动刷新**
>
> Windows 的用户级环境变量是在**进程启动那一刻**复制进去的。
> 所以已经开着的 Codex、PowerShell、VS Code 终端，
> 里面读到的还是**旧值**（或者干脆没有），改多少次都不会自己更新。
>
> 正确的做法是二选一：
>
> - **重启应用**（关掉再开），或
> - **开一个全新的终端窗口**，在里面重新跑
>
> 想确认当前这个终端读到了什么，可以跑（**只会打印有没有配、几个字符，不会打印密钥本身**）：
>
> ```powershell
> python -c "import os; k=os.environ.get('DEEPSEEK_API_KEY',''); print('已配置' if k else '未配置', len(k))"
> ```

> 两种方式同时存在时，**真实环境变量优先**，`.env` 只作兜底。

> ### ⚠️ 不要把真实密钥发到任何地方
>
> 具体说：**不要**贴进聊天窗口、**不要**截图发人、**不要**提交进 Git。
> 这三条都发生过真实事故 —— 截图里的密钥能被 OCR 认出来，
> 而 Git 一旦提交，历史里就永远留着了，删掉文件也没用。
>
> 需要别人帮忙排查时，只发**报错信息**和「配了没配」，
> 不要发密钥本身、前缀、后缀或者前几位。
>
> 万一真泄露了：去 https://platform.deepseek.com 把这个密钥**删掉重建**，
> 不要指望改改 `.env` 就没事了 —— 旧密钥在服务商那边依然是有效的。

### 3. 启动

```bash
python app.py
```

看到这两行就成功了：

```
 * Running on http://127.0.0.1:5000
Press CTRL+C to quit
```

浏览器打开 `http://127.0.0.1:5000`。

> **终端窗口要一直开着**，关掉就等于关掉服务。用完在终端里按 `Ctrl+C` 停止。

**关于调试模式：默认是关的。** 它自带一个可以在浏览器里执行代码的报错页，开到公网上是灾难。
本地确实需要它时才设 `FLASK_DEBUG=1`。

端口也支持用环境变量 `PORT` 改（不设就是 5000）。

### 4. 部署到线上

本地跑和线上跑是**两套不同的启动方式**：本地是 `python app.py`（Flask 自带的开发服务器），
线上是 **Gunicorn**（专门给生产用的）。所以本地能跑 ≠ 线上能跑。

完整的部署步骤写在 **[DEPLOYMENT.md](DEPLOYMENT.md)** —— 目标是 Railway 免费版，内容包括：

- 要设置哪些环境变量、每个是干嘛的
- 为什么要挂**持久卷**，以及不挂会发生什么（**这条最容易踩**）
- **为什么必须只开 1 个 worker**（这条最关键，改错了会出数据问题）
- 部署之后怎么确认数据真的落在持久卷上
- 免费版的额度限制、以及账户被限流时怎么判断
- 出问题怎么排查、怎么回滚

> 部署涉及注册账户、连接仓库、可能产生费用——**这些都要你自己操作，代码里没有、也不该有**。
> 本轮只做了「平台无关的生产化改造」，没有创建任何线上服务。

## 八个设计决定，和为什么

### 1. 为什么输入框用 `readOnly`，而不是 `disabled`

提交之后要把输入框锁住，防止用户继续输入。直觉上会写 `disabled`，但那是错的：

```javascript
input.disabled = true;    // ❌ 被 disabled 的表单控件，浏览器不会提交它的值
input.readOnly = true;    // ✅ 能拦住输入，又照常提交
```

用 `disabled` 的话，后端就收不到用户问的问题了——这个坑很隐蔽，因为界面上看起来一切正常。

### 2. 光靠 `readOnly` 挡不住回车

只读的输入框**仍然可以触发提交**。真正拦住第二次的是脚本里的一个标志：

```javascript
if (sending) { event.preventDefault(); return; }   // 已经在发了，这次回车是多余的
```

这一条和下面第 3 条合起来，才是完整的「防止重复提问」。

### 3. 为什么「锁」必须放在 `finally` 里还

服务器端也有一道防线：同一时间只允许处理一个提问。

```python
try:
    chunks = retriever.retrieve(question, top_k=3)                  # ① 只按【当前问题】找资料
    recent = load_recent_messages(sid)                              # ② 取【本会话】最近几条历史，当上下文
    # ③ 中间还会占一次每日额度；占不到就在这里返回，走不到下面
    result, diagnostic_code = rag.generate_answer_with_context_and_diagnostics(   # ④ 让模型照着资料回答，并校验它引用的来源
        question, chunks, recent, client, MODEL)
    answer = format_answer_with_sources(result)                     # ⑤ 附上「资料来源」
    save_exchange(sid, question, answer)                            # ⑥ 存进数据库
except Exception:
    error = SAFE_ERROR_MESSAGE     # ← 只给一句固定的抱歉，不写 str(e)
finally:
    _lock.release()                # ← 无论成功失败都要还
```

> **两个返回值，去向不同：**
> `result`（三键：decision / answer / citations）是**唯一**进页面和数据库的东西；
> `diagnostic_code`（固定短枚举）**只写进安全日志**，不给用户看、也不落库。
> 它回答的是「这个 decision 是模型主动判的，还是某一关校验没过降级来的」。

> **顺序是有讲究的：先检索，再取上下文。** 检索只拿当前问题，
> 历史**不会**被拼进检索查询——否则「这次能引用什么」会跟着上一轮漂移。

`finally` 是关键：如果出错时忘了还锁，这把锁就**永远拿不回来了**，之后每一次提问都会被当成「有请求正在处理」而拒绝，页面彻底废掉。

> **注意 `except` 那一行没有 `as e`。** 异常原文里可能有内部路径、请求内容甚至密钥片段，
> 用户只需要知道「这次没成」。细节留在服务端就好——这是刻意的，不是漏写。

### 4. 为什么回答完要「跳转」一下

成功了不直接显示页面，而是跳转回首页：

```python
return redirect(url_for("index"))
```

这叫 **POST-Redirect-GET** 模式，是网页开发的标准做法。原因是：如果直接渲染，浏览器地址栏里留的就是「刚才那次提交」的结果，用户一按 F5，浏览器会弹窗问「要重新提交吗」——点「是」就又问了一遍 AI。

改成跳转之后，地址变回普通的 GET，F5 只是重新打开页面，不会重复提问。

### 5. 为什么 AI 的回答要「清洗」过才显示

AI 返回的是 Markdown，页面上用 `marked` 把它转成真正的 HTML 再显示（否则就是一堆星号）。

但 `marked` 只负责转换，**不管内容安不安全**。AI 的输出属于「外来内容」，万一里面藏着 `<script>` 之类的东西，直接塞进页面就会在浏览器里执行。

所以中间加了一道 `DOMPurify` 清洗——多这 20KB，值得。

> 这是个通用原则：**凡是外部来的内容要变成 HTML，必须先清洗。**

### 6. 怎么做到「每个人的对话互不串话」

给每个浏览器发一个**随机的会话 ID**（`uuid4`，32 位十六进制），存在 Flask 的 `session` 里。

关键点：**Flask 的 session 是「签名」的，不是「加密」的。** 区别在于——

- 用户能看到自己的会话 ID（它就明晃晃地存在 cookie 里）
- 但用户**改不了**它。动了任何一个字符，签名就对不上，Flask 直接丢弃

所以别人即使用自己的浏览器照着改，也伪造不出你的会话 ID，自然看不到你的对话。

> 为什么用 `uuid4` 而不是 `1、2、3` 这种自增数字：那样别人把 URL 里的 `3` 改成 `4` 就能看别人的对话了。

### 7. 为什么数据库操作要用 `?` 占位符

```python
# ❌ 千万别这么写
conn.execute("SELECT * FROM messages WHERE session_id = '" + sid + "'")

# ✅ 正确写法
conn.execute("SELECT * FROM messages WHERE session_id = ?", (sid,))
```

把变量直接拼进 SQL 字符串，等于让别人有机会**把 SQL 语句写进你的数据里**——这就是「SQL 注入」。`?` 占位符会让 sqlite3 自动把参数安全地转义好，是唯一正确的写法。

### 8. 网页为什么不再自己调模型

以前 `app.py` 是这样干的：把系统提示词 + **整段**历史记录 + 问题拼一拼，直接发给模型，拿到什么就显示什么。

现在改成下面这条链路，`app.py` 里**一行模型调用都没有了**（模型调用只在 `rag.py` 里发生，而且一次提问只有一次）：

```
问题 → retriever.retrieve()                    只按【当前问题】找出最相关的几段资料
     → load_recent_messages()                  取【本会话】最近几条消息，当对话上下文
     → rag.generate_answer_with_context_and_diagnostics()
     │     让模型照着资料回答、校验它引用的来源；
     │     回两个值：result（三键，进页面和数据库）
     │              diagnostic_code（固定枚举，只进安全日志）
     → format_answer_with_sources()            附上「资料来源」
     → save_exchange()                         存进数据库
```

**为什么要这么绕？** 因为「模型说了什么」和「模型说的话有没有依据」是两件事。

`rag` 拿回来的结果，已经过了六道检查：模型编的文件名会被拦下、说好要回答却没给出处会被拦下、返回坏 JSON 会被拦下……全都安全降级成「证据不足」。**这些事在网页这一层做不了**——那里只该关心「怎么把结果好好显示出来」。

还有一个更实际的理由：**同一套逻辑评测器也在用**。37 道验收题跑的就是 `retriever` + `rag` 这两层。如果网页自己再写一套调模型的代码，那么「评测通过的东西」和「网页实际跑的东西」就不是一回事了——分数再好看也不作数。

> **评测器走的是同一个 `rag` 模块，但用【不带上下文】的入口**（`generate_answer_with_diagnostics()`）。
> 这是刻意的：一道题在评测里和在网页里，不该因为你最近聊过什么而得出不同结果。
> 上下文只影响网页这一侧的体验，不进评测的判分口径 —— 这样分数才可复现、可对比。

> 一句话：**网页只负责端菜，做菜和验菜的事归 `rag.py`。**

### 9. 「资料来源」是怎么来的，为什么不能随便加

用户看到一段回答，末尾写着：

> 资料来源：
> - grammar_present_perfect.md · 基本结构

**大多数人到这里就不查了。** 一个看起来有出处的答案，比没有出处的更容易让人相信——哪怕那个出处是编的。

所以「资料来源」这一节由 `format_answer_with_sources()` 单独负责，规矩只有两条：

1. **只有 `decision == "answer"` 才加这一节。** 拒答和证据不足本来就没给出回答，更没有出处可给。硬给它们加一个来源列表，等于伪造依据。
2. **只显示 `rag.py` 白名单放行的引用。** 模型想引什么就引什么的话，它完全可以编一个不存在的文件名——而用户没法分辨。

存进数据库的是**格式化之后**的整段文字，所以历史记录里也带着来源，刷新页面、重启程序之后看到的都和当时一样。

| **重启后** | 数据在磁盘上，服务器重启不丢 |

| 空输入 | 空问题、纯空格、纯换行都不写数据库、不调 AI、不占锁、也不检索 |
| 原有行为 | POST-Redirect-GET、防重复请求、出错后释放锁、数据库里没有密钥 |
| **邀请码** | 正确的码能进；错的码**一个字都不建**；被作废的码有自己的提示；**码不进 URL、不进页面、不进日志**（明文、摘要、pepper 都查）；尝试超限后被挡住；输码必须带 CSRF token |
| **档案隔离** | A 看不到、也改不了 B 的档案；已绑定的浏览器会话**不能被另一张邀请码改绑**；匿名访客打不开档案页 |
| **档案持久化** | 改档案是覆盖同一行；重启后同一 cookie 仍读得到；非法选项被拒绝且不写库；删学习者时偏好和会话绑定一起级联删掉 |
| **档案进提示词** | 每一项都在发给模型的内容里有对应说法；「不确定」会标注；匿名访客的提示词里**完全不出现档案那一段**；档案**不能**变成引用来源 |
| **清空全部数据** | 聊天记录（**含多设备、含被作废过的旧设备**）、偏好、学习者、会话绑定全删，邀请码作废；**别的学习者和匿名访客一条不动**；**全站额度绝不清**；中途失败整体回滚；旧码和旧会话都进不来 |
| **删除与提问抢跑** | 提问正卡在「调模型」时发起删除 → 删除必须等它结束才提交，**旧请求不能把消息写回来**；等不到锁时明确拒绝且什么都不删 |
| **绑定失效语义** | 作废只打标记不删行（关联要留给删除用）；被作废的会话事后仍能找回它的聊天记录；**本人**拿新码可恢复、**别人**不能接管这个会话 |
| **会话轮换** | 失效的会话会被换成新 ID（新消息不再算到原学习者头上）；健康会话和匿名会话**永不轮换**；旧绑定行**永不删除** |
| **确认不了就停下** | 会话状态读不出来时：**不提问、不兑换邀请码、不写库**，只给一句重试提示（503）。绝不沿用未经确认的旧会话 ID —— 那会把消息写进别人的旧会话 |
| 测试自身 | 用的确实是假密钥、假客户端**和假检索**（防止哪天不小心碰到真 API，或让网页测试被检索结果牵连） |

### 日志里只有「固定诊断标签」，没有正文

每次提问会打一条 `rag_decision`，除了决策、引用数、耗时、上下文条数/字符数，还带一个 `diagnostic_code`：

| 标签 | 意思 |
| --- | --- |
| `ok` | 模型主动给出了这个决策，且通过了全部校验 |
| `invalid_json` | 模型没按 JSON 格式回，被安全降级 |
| `invalid_citations` | 引用了本次片段之外的来源（编的，或引了没给它的），被降级 |
| `citations_on_general_answer` | 通用知识回答却带了引用，被降级 |
| `api_or_response_error` | 接口层就没成功，压根没拿到模型输出 |
| 其余固定枚举 | 空正文、缺引用、decision 非法等，逐个对应一道校验 |

**为什么要这个标签：** 只看最终的 `decision`，「模型真的判了证据不足」和「模型返回坏 JSON、被降级成证据不足」长得一模一样，但排查方向相反——前者要动提示词，后者要查模型输出或校验规则。

**标签里有什么：** 只有上面这些写死的短词。**没有**模型原文、异常内容、用户问题、AI 回答、上下文或密钥。它**不会**出现在页面上，也**不会**写进数据库——页面和数据库拿到的永远只是 `decision` / `answer` / `citations` 三个键。

## 学习档案（邀请码 + 偏好）

### 怎么用

1. 打开 `/invite`，输入邀请码 → 这个浏览器就认领了一个**学习者身份**
2. 打开 `/profile`，填 5 项偏好：**英语水平 · 学习目标 · 重点提升方向 · 回答长度 · 中英对照**
3. 回到对话页提问 —— AI 会按档案调整**难度、长度、用词和表达方式**

档案随时可改、也可以清空（见下），改完立刻生效。没有任何邀请码的访客照常能用对话，只是不带个性化。

### 档案里存什么、不存什么

| | |
| --- | --- |
| **存** | 内部编号、创建/最近活跃时间、5 项偏好的**代号** |
| **不存** | 姓名、学校、邮箱、联系方式等任何身份信息；也**不存用户的原话**（全部是白名单代号） |

邀请码在数据库里**只存 HMAC 摘要**，不存明文 —— 拿到数据库文件但没有 `INVITE_CODE_PEPPER` 也算不出任何一个码。
它**不会**出现在 URL、页面或日志里。

### 邀请码就是你的凭证

- **它不绑定某一台设备。** 换一台电脑、或者清掉浏览器 cookie 之后，
  只要**这张码还在你手里**，重新输入就能回到**同一份档案**
  （这正是把邀请码和学习者拆开存的意义）。
- **但它也不绑定某一个人**：谁拿到这张码，谁就能访问这份档案。请当成密码保管，不要转发。
- **丢了就找不回来。** 库里只有摘要，就算是我们也没法把明文还原出来；
  而按编号补发需要身份核验，项目现在没有 —— 所以**丢了就是丢了**（见上面的说明）。
  发放邀请码时就要跟用户讲清楚这一点。
- **作废是不可逆的。** 它会让那位学习者永久失去入口；数据还躺在库里，但没法安全地还给谁。

### 组织者命令行（发码 / 作废）

邀请码是「组织者生成 → 手动发给用户」的，入口在命令行（网页上**故意没有**发码按钮：
这一版没有管理员登录，做一个不设防的发码页等于让任何人都能给自己发一个码）。

```powershell
python profile_store.py new-invite        # 生成一张新码（只显示这一次）
python profile_store.py revoke <码>       # 作废：同时断开已绑定的会话
python profile_store.py stats             # 看统计，只报数量、不显示任何码
```

**「作废」到底做了什么**（这一条很容易被想当然）：

| | |
| --- | --- |
| ✅ 做了 | ① 这张码不能再用来进入；② 这位学习者名下**所有会话**都置为失效（不是删行 —— 见下），已经进来的浏览器下次请求就查不到档案，会被引导回输码页；③ 那台浏览器会被**换一个新的会话 ID** |
| ❌ 没做 | 不删学习者、不删偏好、不删聊天记录 —— 目的只是**断开进入通道**，不是销毁数据 |
| ⚠️ **旧历史不再显示** | 因为会话 ID 换了，那台浏览器回到「还没有对话」的样子 —— **它连自己之前问过的话也看不到了**。数据并没有丢：旧消息仍然挂在旧会话 ID 下，而且那条绑定记录还在（只是标了失效），所以**以后「清空全部个人数据」照样找得到、删得掉** |
| 🆕 **之后它是全新访客** | 失效之后它再提问，消息落在**新的**会话 ID 下，**不会再算到原来那位学习者头上** —— 所以以后清空他的数据时，也不会误删这些无关的提问 |
| ⛔ **不可逆** | **作废之后没有找回原档案的路。** 数据还在库里，但没有身份核验手段，无法确认归属（见下） |

### ⛔ 邀请码丢了 = 找不回原档案（当前状态）

**`reissue`（按学习者编号补发）命令已经停用** —— 输入它会得到一段解释。

停用的理由：补发是「绕过唯一凭证」的操作，而项目**没有任何身份核验手段**
（没有账号、没有密码、没有邮箱验证）。而学习者编号是自增的，猜都猜得到 ——
能用编号补发，就等于**谁都能拿到别人的档案**。与其留一个看起来能恢复、
实际是冒领入口的命令，不如先关掉。

| | |
| --- | --- |
| **数据还在吗** | 在。档案、偏好、聊天记录都完好地存在库里 |
| **能还给本人吗** | **目前不能** —— 我们无法安全地确认「来要码的人」就是那位学习者 |
| **对用户怎么说** | 只能说：**这个码是你唯一的凭证，请自己保存好；丢了没法恢复**（邀请码页上就是这么写的） |
| **要恢复这个能力** | 得先设计一套身份核验（比如组织者线下确认 + 一次性复核流程），这属于上线前必须解决的问题 |

> 这也让**作废**变得更重：它是**不可逆**的。所以作废只适合「码泄露、必须立刻止血」这类场景；
> 如果只是普通用户丢了码，作废帮不上他。

### 关于「不用于训练」

| | |
| --- | --- |
| ✅ **可以承诺** | 本项目**不主动用你的内容训练自己的模型** |
| ✅ **必须说明** | 生成回答要把**必要的内容**（你的问题、检索到的资料片段）发送给**第三方模型服务商** |
| ❌ **不能承诺** | 「你的内容绝不会被用于训练」—— 那取决于第三方，我们无权保证 |

### 清空学习档案（只清偏好）

档案页上有一个「清空学习档案」按钮，需要**勾选确认**并带 CSRF token 才能生效。

| | |
| --- | --- |
| **会清掉** | 那 5 项偏好。清完之后档案页显示「未设置」，之后的回答按**默认偏好**生成 |
| **不会动** | 学习者身份、邀请码、**聊天记录**、会话绑定 —— 你还能用同一张码继续用，只是从零开始积累 |

> ⚠️ **它不是「清空全部个人数据」**，两者差得很远 —— 见下一节。
> 清空偏好**也不会**影响第三方模型服务商那边可能已经保留的数据。

### 清空全部个人数据（不可撤销）

档案页上另有一个更重的入口，同样需要**勾选确认**并带 CSRF token。

| | |
| --- | --- |
| **会删掉** | ① 全部**聊天记录**（这个学习者名下**每一台设备**的，包括已经被作废过的旧设备的）② 5 项**学习偏好** ③ **学习者身份**本身 ④ 全部**会话绑定** |
| **会被作废** | 他名下所有**邀请码** —— 行保留（那是「谁用过」的痕迹），但状态改成 revoked，**旧码从此不能再用** |
| **不会动** | 其他学习者、匿名访客的聊天记录、**全站每日额度**（那是全站共用的计数器，不属于任何个人） |
| **删除之后** | 这个浏览器退回「未认领」状态；旧码也进不来 —— 想继续用只能拿一张全新的码，那是**另一个人** |

**它做不到的事（不承诺）：**

- **不等于物理擦除。** 数据库文件里的历史页、以及任何备份或快照，不会因为这次删除而消失；
  那些需要另外的彻底销毁流程。
- **管不了第三方。** 生成回答时，你的问题会发给模型服务商；对方那边可能保留的记录，
  我们无权也无法删除。
- **同时进行的提问会被等完再删。** 删除要和「处理提问」共用一把锁：
  正在回答的那个问题会先跑完（连同它写库），然后才执行删除 ——
  所以不会出现「删完又被旧请求写回来」。删除时如果等不到锁，会明确告诉用户稍后再试。

> 实现见 `profile_store.clear_all_data()`：整个过程在**同一个 SQLite 事务**里，
> 顺序是「先找出全部会话（含已失效的）→ 删这些会话的聊天记录 → 删偏好 →
> 作废邀请码 → 删会话绑定 → 删学习者」，任何一步失败整体回滚。

### 两条边界（重要）

- **档案影响「怎么说」，不影响「说什么依据」。** 它不能给回答提供引用 ——
  引用永远只能来自本次检索到的片段。档案里就算写着某个文件名，模型引了也会被拦下。
- **这不是账号系统。** 没有密码、没有登录，身份靠邀请码认领；所以「隔离」的强度取决于
  邀请码有没有保管好。

## 已知限制

- **只记得最近 6 条，而且只记得这台设备。** 同一个浏览器会话里，最近的 **6 条**消息会作为**对话上下文**带给模型
  （单条最多 1200 字，合计最多 4000 字；超了先丢最老的，最近的一定保留）。
  所以「刚才那句」「再给一个例子」「为什么这样改」这类追问接得上。
- **更早的指代仍然不保证。** 隔了七八轮之后再说「那它呢？」，那一条早就被挤出上下文了。
  **这里面没有长期记忆**：它不是学习档案，不会记录你常犯的错、不记录你学过的词，
  也不跨浏览器、不跨设备、不同步 —— 换台设备打开就是一个全新会话。
- **检索只按当前这个问题。** 上下文只用来理解你在指代什么，**不会被拼进检索查询**；
  引用也仍然只能来自**本次检索到的片段** —— 上下文里出现过的来源名不算数。
  这是刻意的边界：宁可说「证据不足」，也不要让一句「上次那个资料」变成无法核对出处的话。
- **回答有两种来源，请看清标识。** 有资料依据的会列出「资料来源」；没有资料但属于正常英语问题的，会标明「**AI 通用知识回答**」——
  **后者没有项目资料作依据，内容需要你自己判断**，别当成有出处的答案。
- **课程业务事实绝不猜测。** 资料完全没有相关信息时会明确拒答；资料提到了相关服务或机制、但不足以确认具体事项时，会说明证据不足。例如，资料提到学习群和答疑机制，但没有说明是否提供一对一辅导，因此不能回答‘有’或‘没有’。
- **检索用的是关键词匹配，不是语义检索。** 换个说法（比如问「英文时态」而资料里写的是「现在完成时」）可能就找不到了。原因和取舍写在 `RETRIEVER.md` 里。
- **清掉浏览器 cookie 就找不回历史了。** 会话 ID 存在 cookie 里，cookie 没了就相当于换了个新身份。旧记录还躺在数据库里，但没有任何入口能再访问到——等于变成孤儿数据。
- **只能看到一个会话。** 没有「新建对话」「历史会话列表」「重命名」这些功能。
- **删除是「全有或全无」，没有「只删某一段对话」。** 用户可以清空**全部**个人数据（见上），
  也可以只清空学习偏好；但没有「删掉这一轮对话」这种更细的入口 —— 想删就全删。
- **删除不等于物理擦除。** 数据从表里删掉了，但 SQLite 文件里的历史页、以及任何备份或快照
  不会因此消失。真正要做到「不可恢复」，得另外设计（例如删库重建、备份轮换）。
  第三方服务商那边的记录同样不在我们的控制范围内。
- **删除和「正在进行的提问」的关系**：删除会等当前提问处理完再执行（共用一把锁）；
  等不到锁时会明确提示稍后再试，不会硬来。这把锁只在单进程内有效 —— 多 worker 部署时
  这个保证不成立（见下面的「那把锁」）。
- **限流只有一个「全站每日额度」。** 每天最多调用 `DAILY_API_LIMIT`（默认 50）次模型，超过就返回「今天额度用完了」。
  额度按 UTC 日期算，存在数据库里，重启不会归零。
  **但它是保护演示费用的保险丝，不是生产级限流**：不区分用户（没有登录）、不做按 IP 的频率限制、没有验证码，
  也挡不住「一个人把全站额度用完」——50 次用完就大家一起等明天。真要对外提供服务，这块得重新设计。
- **那把锁只在单个进程内有效。** 所以部署时**必须只开 1 个 Gunicorn worker**：
  多 worker 会让「防重复提交」失效（每个进程一把独立的锁），也会让多个进程去抢同一个 SQLite 文件。
  详见 [DEPLOYMENT.md](DEPLOYMENT.md) 第四节。
- **调试模式默认关闭。** 本地确实需要时才设 `FLASK_DEBUG=1`。默认关是刻意的——
  调试模式的报错页等于让人在你服务器上执行代码，绝不该出现在公网上。
- **没有用户系统。** 这是有意为之（需求明确排除了），所以这里的「隔离」是**按浏览器**，不是**按人**——同一个人换台电脑就是新会话。
  给学习档案用的邀请码也是这个道理：它证明「你拿到了一个码」，**不证明你是谁**。
- **档案页只能「清空全部偏好」，不能删单条。** 清空已经做了（带二次确认 + CSRF）；
  但设计文档还要求「删掉某一个记错的生词 / 某一条不该记的错误」，那些功能本身还没有，
  所以也没有对应的删除入口。
- **「清空全部个人数据」已经做了**（档案页入口 + CSRF + 二次确认 + 单事务 + 与提问互斥），
  不再是阻塞项。剩下的相关缺口只有两条：**「删掉单条记录」**（功能本身还没有）和
  **物理擦除**（见上面的「删除不等于物理擦除」）。
- **🔴 没有身份核验，因此「补发邀请码 / 找回原档案」这条路是断的。** 邀请码是唯一凭证，
  一旦丢失或被作废，那位学习者就**永久失去**自己的档案 —— 数据还在库里，但没有任何安全的办法
  确认该把它还给谁（`reissue` 命令已因此停用）。**这是上线的阻塞项**：
  在补上身份核验之前，不能承诺「档案可以恢复」，也不该把作废做成常规操作。
- **作废邀请码本身不会删聊天记录。** 作废做的是：旧码不能再用、已有会话失去访问权、
  那台浏览器换一个新的会话 ID。要让聊天记录真的消失，得走**「清空全部个人数据」** ——
  那才是删记录的操作。两者是分开的，别把「作废」当成「删除」。
- **作废之后，那台浏览器看不到自己之前的历史了。** 因为它被换了新的会话 ID。
  数据还在服务器上（旧消息挂在旧 ID 下，绑定记录也标着失效留着），
  但页面不再显示 —— 这是刻意的：一个身份失效之后，不该继续拿着旧身份的数据看。
  顺带一个副作用要说清楚：**同一台浏览器作废之后问的话，不再属于原来那位学习者**，
  所以以后清空他的数据时，这些提问不会被删掉（那本来就不是他的了）。
- **CSRF 保护只加在新增的两个表单上。** 输邀请码和改档案都有 token；**对话提交那条路还没有**（它是加这个功能之前就存在的表单）。
  按设计文档的清单，需要保护的是「修改偏好 / 删除 / 清空 / 清空全部数据 / 输入邀请码」，对话不在清单里；
  但它确实会写数据，所以这是一处**已知的不一致**，不是「已经做完了」。
- **邀请码限速只存在内存里。** 重启进程就清零，多 worker 部署时各算各的（和那把防重复的锁一样）。
  它抬高的是暴力枚举的成本，**不是生产级风控**。真要对外用，应该像每日额度那样落库。
- **还没有「每位学习者的每日额度」。** 设计文档里有一张 `learner_api_usage` 表解决「一个人把全站额度用完」，
  本轮没做 —— 所以现在仍然只有全站一个额度，上面那条限制继续成立。

## 接下来可以做什么

- 「新建对话」按钮，支持一个浏览器里开多个会话
- 「删掉单条记录」入口（现在只能「清空偏好」或「清空全部数据」，中间那一档没有）
- 「清空全部数据」之后真正意义上的不可恢复（删库重建 / 备份轮换）
- 清理长期没人访问的孤儿会话
- 加用户系统，把「按浏览器隔离」升级成「按人隔离」
- 支持流式输出（一个字一个字往外蹦，而不是等全部想完才显示）
